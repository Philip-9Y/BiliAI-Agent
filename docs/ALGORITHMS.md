# Study-AI 算法全景与质量评估

> 这里讨论计算机科学里的经典算法：排序、查找、哈希、贪心、动态规划、分治、回溯、图、随机化、近似、缓存、调度、字符串、数值优化等。
> 不是“动态分析/运行时分析”这个测试概念。项目里确实有运行时指标，但那是遥测，不是算法。

## 2. 这些算法在代码里怎么走

### 2.1 文字问答

```text
输入
→ 构造字符 bigram / token
→ BGE 向量
→ 关键词余弦 + 字符余弦 + 语义余弦
→ 排序取前 5
→ 拼进 system prompt
→ Agent / 流式回答
```

### 2.2 截图问答

```text
截图
→ 图片编码
→ 云端视觉模型
→ 工具循环（最多 8 步）
→ 保存消息
```

### 2.3 长对话

```text
消息总字符 > 18000 且 > 12 条
→ 旧消息压缩成摘要
→ 保留最近 12 条
→ 摘要 + 最近消息 + 记忆
```

### 2.4 大规模记忆

```text
记忆向量数 ≥ ann_threshold（默认 128）
→ LSH 多表取候选
→ 候选做精确余弦
→ 关键词命中仍参与
```

## 3. 算法质量评估：哪里写得不行

下面不是“有没有算法”，而是“算法在当前实现下的实际缺陷、触发场景、用户会看到什么”。

### 3.1 模型路由是规则贪心，不是智能调度

**现状**

```python
is_simple = len(question) <= 300 and not TOOL_OR_VISION_REGEX.search(question)
```

然后：

- 简单 → 本地；
- 有图/工具关键词 → 云端；
- 本地失败 → 云端。

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| “帮我算一下 12345×6789” | 没有工具关键词，可能被本地 3B 接住，算错也不触发云端 |
| “根据这页 PPT 出 5 道题” | 短、无“工具”关键词，本地可能给出泛泛回答 |
| “把刚才的代码改成 Python” | 可能命中“代码/帮我”关键词走云端，也可能被本地误接 |
| 本地模型回答“看起来合理但错误” | 不抛异常、不为空，不会回退云端 |
| 问题短但需要多步工具 | 规则无法识别意图，误判为简单 |

**本质**

这是**单特征阈值 + 关键词黑名单**，没有：

- 意图分类；
- 工具需求概率；
- 本地模型置信度；
- 历史成功率；
- 成本/延迟预算；
- 在线学习。

**改进方向**

- 特征化路由：长度、代码/公式密度、是否含指代、历史工具使用、图片、领域；
- 小分类器/逻辑回归或 LLM 轻量路由；
- 本地回答后做质量检查（空、过短、格式不合法、拒答）再决定是否云端复核；
- 记录每条路由的成功率，做成本-质量帕累托。

---

### 3.2 混合检索的权重是拍脑袋的

**现状**

```text
score = overlap × 2 + char_cosine × 4 + semantic × 8
阈值：overlap=0 且 char<0.18 且 semantic<0.38
```

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| 两条记忆都含“递归树” | 常见 bigram 让无关记忆得分高 |
| 长记忆 vs 短记忆 | 长文本 gram 多，overlap 天然更大，长度偏置 |
| 用户问“主定理” | 关键词精确命中，但语义分可能把泛泛的“算法复杂度”排前面 |
| 用户问“这个为什么” | 依赖 prior_questions 拼接，拼接长度会稀释语义 |
| BGE 相似度只有 0.40 左右 | 阈值 0.38 接近边界，容易漏/误召回 |

**本质**

- 没有 IDF：常见词和罕见词同权；
- 没有 BM25；
- 没有分数归一化/校准；
- 权重 2/4/8 是手工常数；
- tags 和正文同权；
- 没有 rerank；
- 没有检索评测（recall@k）。

**改进方向**

- BM25/TF-IDF + 向量混合；
- 权重配置化并用评测集调参；
- 加 cross-encoder rerank；
- 对记忆长度做归一化；
- 记录每次召回的 hit/miss。

---

### 3.3 LSH ANN 的召回不稳定

**现状**

- 4 张表 × 8 bit 随机超平面；
- 查询取桶并集；
- 没有 multi-probe；
- 没有增量更新；
- 没有召回率评估；
- 固定随机种子。

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| 记忆 1000 条，相关记忆落在不同桶 | 候选集没有它，语义分为 0 |
| 两条语义相近但哈希位不同 | 只能靠关键词兜底；纯语义问法会漏 |
| 候选集非空但恰好漏掉目标 | 不会回退全量扫描，直接漏 |
| 新增一条记忆 | 整个索引重建，O(M×T×B×D) |
| 记忆 128 条刚过阈值 | 建索引成本可能高于直接线性扫描 |

**本质**

- 这是**近似**算法，但没有 recall 指标；
- 没有多表探测；
- 没有候选不足时回退；
- 没有持久化索引；
- 阈值 128 是经验值，没有 benchmark。

**改进方向**

- 多探测 LSH / HNSW / FAISS；
- 候选不足自动回退线性；
- 增量插入；
- 记录 recall@5、延迟、内存；
- 用真实记忆集评测，而不是拍阈值。

---

### 3.4 长对话摘要会丢关键约束

**现状**

- 字符阈值 18000；
- 保留最近 12 条；
- 旧消息最多取 24 条、总字符约 8000；
- 用 LLM 生成不超过 400 字摘要。

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| 长实验报告，前面有公式/参数 | 摘要可能只保留结论，丢公式/单位/边界 |
| 用户前面说“必须用中文/必须给代码” | 摘要可能丢失风格约束 |
| 很早的关键定义 | 被压缩成一句话，细节丢失 |
| 摘要模型幻觉 | 摘要引入原文没有的内容 |
| 一条消息特别长 | 仍可能撑爆上下文，因为阈值按字符不是 token |

**本质**

- 没有 token 计数；
- 没有重要性/时间衰减；
- 没有“必须保留”的 pin；
- 摘要没有校验；
- 只保留摘要，不保留可检索的旧原文。

**改进方向**

- token-aware 预算；
- 关键实体/公式/约束抽取后固定保留；
- 旧消息原文入 FTS/向量库，按需回查；
- 摘要做事实一致性检查。

---

### 3.5 记忆合并用字符相似度，语义并不可靠

**现状**

```text
difflib.SequenceMatcher(...).ratio() >= 0.72 → 合并
```

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| “用户喜欢深色主题” vs “用户喜欢浅色主题” | 字符很像，可能被错误合并 |
| “递归树复杂度” vs “递归树时间复杂度” | 可能该合并但没到 0.72 |
| 同义不同词 | 字符相似度低，不合并，记忆重复 |
| 否定句 | “喜欢” vs “不喜欢” 字符相似，可能合并错误 |

**本质**

- 字符级比较，不理解语义/否定；
- 阈值固定；
- 没有来源/时间/置信度；
- 合并后保留较长文本，可能丢旧信息。

**改进方向**

- 向量相似度 + NLI 矛盾检测；
- 保留 provenance；
- 冲突时不要覆盖，转为“两个版本”；
- 合并前做 schema 校验。

---

### 3.6 Agent 工具循环没有规划、没有环检测

**现状**

```text
最多 8 步
每步：模型 → tool_calls → 执行 → 回填
没有显式计划
没有重复调用检测
没有每工具重试
没有并行
```

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| “整理这章并插入 Word” 需要 10 步 | 第 8 步直接失败 |
| 工具连续报错 | 模型可能重复同一调用，浪费步数 |
| 两个独立工具可并行 | 串行执行，慢 |
| 长工具执行中用户点停止 | 只能等当前工具返回，不能立即中断 |
| 工具返回巨大文本 | 全量回填，撑大上下文 |

**本质**

- 有界迭代搜索，不是 Plan-and-Execute；
- 终止条件是步数，不是任务完成；
- 没有状态图/检查点；
- 没有预算（token/时间/费用）控制。

**改进方向**

- 显式计划 + 执行状态；
- 重复调用检测/环检测；
- 每工具超时与重试；
- 并行独立工具；
- 工具输出摘要/截断；
- 断点恢复。

### 3.7 Top-K 已用堆，但仍要全量打分

**现状**

```python
heapq.nlargest(limit, scored, key=...)
```

**问题场景**

- 只需要前 5 条，但每条记忆仍要算关键词/字符分，O(M)；
- 只有语义分走 ANN，关键词仍全量；
- 记忆很多时，主要成本在加载和打分，不在排序。

**改进方向**

- BM25 倒排索引；
- 先 ANN/关键词候选，再对候选精排；
- 分页/增量加载。
### 3.8 缓存没有统一失效/容量策略

**现状**

- `render_answer` LRU 64，key 只有文本；
- 公式 PNG 用 SHA1 文件缓存，没有全局容量上限；
- 浏览器桥 TTL 20 秒；
- embedding 用 `model+text` 哈希。

**问题场景**

| 场景 | 会发生什么 |
| --- | --- |
| 改主题/字号 | 公式 key 含主题时没问题；但 HTML LRU 只按文本，可能显示旧样式 |
| 长期使用 | `data/math_cache` 持续增长 |
| 记忆内容修改 | hash 变化会重算，正确 |
| 多进程 | 文件缓存没有锁，可能重复渲染 |

**改进方向**

- LRU 缓存带上渲染配置版本；
- 公式缓存定期清理/容量上限；
- 文件锁或原子写。

### 3.9 SQLite 搜索是 `%LIKE%`，不是全文索引

**现状**

- 会话搜索 `LIKE '%query%'`；
- 没有 FTS5；
- 记忆列表全量加载。

**问题场景**

- 会话很多时，搜索全表扫描；
- 中文分词没有，搜索“递归树”可能匹配不到分词变体；
- 记忆多时每次检索把所有记忆读进内存。

**改进方向**

- SQLite FTS5；
- 记忆分页/候选预筛；
- 向量单独存储与索引。

---

### 3.10 重试可能重复计费

**现状**

- 连接失败/429/5xx 自动重试 2 次；
- 没有幂等键；
- 超时后重试可能已经产生一次云端生成。

**问题场景**

- 网络超时但服务端已生成 → 重试再生成一次，token 翻倍；
- 429 没有 jitter，多个请求同时重试；
- 流式请求中途失败不会重试。

**改进方向**

- 幂等请求 ID（如果服务支持）；
- 指数退避 + 随机抖动；
- 熔断；
- 记录每次重试成本。

---

### 3.11 沙箱是进程隔离，不是内核沙箱

**现状**

- 独立子进程；
- 12 秒超时；
- 清环境变量；
- 固定 cwd。

**问题场景**

- 插件仍可读写本机文件；
- 插件仍可访问网络；
- 插件可以起子进程；
- 没有 CPU/内存限额；
- 没有插件签名/权限强制执行。

**本质**

- 解决了“崩溃/卡死/环境变量泄露”，
- 没有解决“恶意插件偷文件/联网”。

**改进方向**

- Windows AppContainer / Job Object；
- 文件白名单；
- 网络禁用；
- 插件签名；
- 资源限额。

---

### 3.12 热键备用是贪心尝试，不是全局冲突求解

**现状**

- 原键失败 → 加 Shift 再试；
- 不询问用户；
- 没有全局键位规划。

**问题场景**

- 原键和 Shift 键都被占用 → 该功能仍不可用；
- 多个功能争同一备用键；
- 换键盘布局/输入法时行为变化。

**改进方向**

- 冲突时弹出可选键位；
- 保存用户自定义键位；
- 启动时做全局冲突报告。

## 5. 复杂度总览

- bigram：O(L)
- 稀疏余弦：O(G)
- BGE 余弦：O(D)，D=512
- 线性记忆检索：O(M×D)
- LSH 建索引：O(M×T×B×D)
- LSH 查询：O(T×B×D + C×D)
- Agent 工具循环：O(S×T)，S≤8
- Top-K：O(M log K)，但仍需对全部记忆算关键词分
- 记忆去重：O(n×m)
- 公式缓存：O(1) 哈希 + 文件 I/O

## 6. 结论

项目里真正用到的经典算法是：

1. **排序**（Timsort / SQL ORDER BY）
2. **查找**（线性、字典、B-tree）
3. **哈希**（SHA1、dict、LSH）
4. **贪心启发式**（本地优先、最近窗口、Shift 备用）
5. **随机化/近似**（LSH）
6. **相似度**（余弦、SequenceMatcher）
7. **缓存**（LRU、TTL、哈希缓存）
8. **指数退避**
9. **堆 Top-K**
10. **有界迭代搜索**（Agent 工具循环）

没有使用：

- 动态规划
- 分治
- 回溯
- 分支限界
- 图算法
- 并查集
- Trie/AC 自动机
- 布隆过滤器
- 线性规划/梯度下降/遗传算法

当前最需要优化的不是“再加一个 DP”，而是：

1. 模型路由从规则升级为可评估的分类器；
2. 检索从手工权重升级为 BM25/向量/rerank 的可评测组合；
3. ANN 从固定 LSH 升级为有 recall 指标的多探测/ HNSW；
4. Agent 从有界循环升级为计划/检查点/环检测；
5. 摘要从字符阈值升级为 token 预算 + 关键约束保留。
